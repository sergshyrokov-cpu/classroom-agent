# US-013 Entity Model — Background synchronization service

One new Domain entity, one new Application port, one new Application model, one
changed existing query. No entity of another Story changes.

## 1. `SyncState` — the new entity

`ClassroomAgent.Domain/Entities/SyncState.cs`. The business concept is
`trebovaniya.md` §3's `SyncState`: the status of background synchronization with
the Classroom API. The glossary term is "синхронизация" / a *run* of it.

### 1.1 Properties

| Property | Type | Business concept | Notes |
|---|---|---|---|
| `Id` | `long` | — | surrogate key (PC-3) |
| `Status` | `SyncRunStatus` | running / completed / failed (§3) | the closed three-value vocabulary |
| `RunId` | `Guid` | the run, as the log names it | generated by the caller of the factory, never parsed from input (spec VR-003) |
| `StartedAt` | `DateTimeOffset` | when the run began | UTC (PC-6) |
| `FinishedAt` | `DateTimeOffset?` | when it ended | null exactly while running |
| `ProcessedCount` | `int` | "счётчик" (§3) | one counter (spec I-8); zero while the pipeline is empty (spec I-1) |
| `LastError` | `string?` | "последняя ошибка" (§3) | category plus short message; null unless failed |
| `LastSuccessfulRunAt` | `DateTimeOffset?` | "время последней синхронизации" (§3) | only a completed run writes it |
| `CreatedAt` / `UpdatedAt` | `DateTimeOffset` | — | PC-6, stamped by the interceptor |

### 1.2 Behaviour

Private parameterless constructor for EF Core, as `LegitimacyState` has. The
entity is the only place the state machine lives:

| Member | Effect | Rule it enforces |
|---|---|---|
| `static SyncState BeginRun(Guid runId, DateTimeOffset startedAt)` | a new row in `Running`, counter zero, no error, no successful run yet | the row is created by the first run (spec I-2) |
| `void BeginRun(Guid runId, DateTimeOffset startedAt)` | the existing row moves to `Running`: new run id, new start, counter reset to zero, `LastError` cleared, `LastSuccessfulRunAt` **kept** | one row updated in place (OD-004); a new run never erases the last success |
| `void CompleteRun(DateTimeOffset finishedAt, int processedCount)` | `Completed`, end instant, counter, **and** `LastSuccessfulRunAt = finishedAt`; `LastError` stays null | a completed run is the only writer of the last-success instant (spec FR-008) |
| `void FailRun(DateTimeOffset finishedAt, int processedCount, string error)` | `Failed`, end instant, counter reached, the error; `LastSuccessfulRunAt` **untouched** | spec FR-008 — the Owner sees both the last success and the current failure |
| `bool IsRunning => Status == SyncRunStatus.Running` | reading convenience | — |

Rules the entity enforces by throwing `ArgumentException` / `ArgumentOutOfRangeException`:

- `CompleteRun` and `FailRun` are valid only from `Running` — a terminal row cannot
  be completed twice;
- `processedCount` is never negative;
- `error` is neither null nor blank, and is **truncated to 512 characters** before
  being stored, so a long message becomes short instead of failing at commit
  (db-design §3.3);
- `finishedAt` is never earlier than `StartedAt`.

The entity holds **no policy number**: the interval is not a field, not a
parameter and never reaches it (AD-3; the US-012 precedent, where the lockout
numbers arrive as arguments from `Application`). It also holds no clock — every
instant arrives as an argument from the `TimeProvider` (spec VR-006).

There is **no** `CancelRun`: `trebovaniya.md` §3 defines three statuses and spec
I-3 decided that a stale `Running` row is tolerated rather than described by a
fourth.

## 2. `SyncRunStatus` — the new enum

`ClassroomAgent.Domain/Enums/SyncRunStatus.cs`, exactly three members: `Running`,
`Completed`, `Failed`. Persisted as the codes `running` / `completed` / `failed`
through a value converter in the entity configuration, the way
`InstallationStatus` and `CompatibilityState` are (db-design §3.1). No `Unknown`
and no `None` member — the never-run state is the absence of the row (spec I-2).

## 3. `ISyncStateRepository` — the new port

`ClassroomAgent.Application/Ports/ISyncStateRepository.cs`, implemented in
`ClassroomAgent.Infrastructure/Persistence/Repositories` (AD-3, AD-4). No EF Core
type appears in the interface.

| Member | Purpose |
|---|---|
| `Task<SyncState?> GetAsync(CancellationToken)` | the single row for writing, or null when the installation has never synchronized |
| `Task<SyncState?> GetForReadAsync(CancellationToken)` | the same row for reading, no tracking — the `ILegitimacyStateRepository` pairing |
| `void Add(SyncState state)` | stage the first row; committed through `IUnitOfWork` |

**No delete member is added anywhere**, and `SaveChangesAsync` stays on
`IUnitOfWork` (the existing shape) rather than on this port.

## 4. `SynchronizationRunOutcome` — the new Application model

`ClassroomAgent.Application/Models/`. The three shapes spec FR-005 fixes, modelled
exactly as `StartupSelfCheckOutcome` already is — a sealed record with static
factories and no behaviour:

| Factory | Carries | Meaning |
|---|---|---|
| `Ran(Guid runId, int processedCount, string? error)` | the run's identity and result | the run happened; `error` non-null means it failed |
| `SkippedReadOnly(LegitimacyModeReason reason)` | the read-only reason | refused by the guard; **nothing was written** (spec FR-007) |
| `SkippedConnection(WorkspaceConnectionState state)` | the connection state | no usable connection; nothing written |

The background service maps each shape to one log line (spec FR-012); no shape
becomes a response body, because the Story has no endpoint (api-design §1).

## 5. Existing types this Story changes

| Type | Change | Why |
|---|---|---|
| `GetReadinessQuery` (`Application/UseCases`) | one more `Unhealthy` condition: the synchronization background service is not running | DC-11, spec FR-014. Read-only mode must keep returning `Degraded`. Code US-005 owns — the `implementation_report` traces it. |
| `InstallationSettings` (`Web/Configuration`) | one new member for the run interval | spec FR-013, read by `InstallationSettingsReader` from `Sync:IntervalMinutes` |
| `ClassroomAgentDbContext` | one new `DbSet<SyncState>` | four sets become five |

Nothing else changes. In particular **`PermittedServiceWrites` does not grow**: the
run use case calls `IReadOnlyModeGuard` first, so it is a protected write path, not
a service write permitted in read-only mode (spec FR-006), and BR-026's closed list
stays as it is.

## 6. Mapping to API DTOs

**None.** This Story exposes no endpoint, page or DTO (api-design §1, spec FR-016),
so no entity is mapped to a wire type — and AD-8's rule that a Domain entity never
appears in a controller signature or view model is satisfied trivially. US-024 will
define the read model that shows this row; nothing in this Story anticipates its
shape.
