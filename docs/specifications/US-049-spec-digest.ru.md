# US-049 — коротко по-русски: ключи сессий шифруются на диске

## 1. Что изменится для пользователей

На экранах не меняется ничего.

- **Владелец, Админ, Декан.** Ключи, которыми программа подписывает вход и
  формы, теперь лежат на диске зашифрованными средствами Windows. Скопированная
  папка с ключами бесполезна под другой учётной записью того же компьютера и на
  другом компьютере — подделать вход по ней нельзя. (FR-001, FR-002)
- **Перезапуск службы** под той же учётной записью по-прежнему никого не
  разлогинивает. (FR-006)
- **Если программу запустить под другой учётной записью** (или принудительно
  сбросить пароль учётной записи службы), старые ключи не прочитаются: программа
  всё равно запустится, создаст новый ключ, а всем придётся войти заново. Данные
  не теряются. (FR-003)
- **Ключи, записанные до этой Story**, читаются, пока не истекут; все новые —
  только зашифрованные. (FR-004)
- **Не на Windows** программа не запускается и пишет причину. (FR-005)
- **Владелец при развёртывании** первый запуск из консоли делает под учётной
  записью службы и проверяет права на папку ключей — это уже записано в
  инструкции развёртывания (DC-2). (FR-007)

## 2. Решения, которые нужно подтвердить

- **I-1 Нечитаемый ключ пропускается, а не удаляется** (FR-003). Программа не
  падает и файл не трогает — создаёт рядом новый. Так написано в требованиях
  («придётся войти заново; данные не теряются»), а если позже запустить под
  правильной учётной записью, старый ключ снова прочитается.
- **I-2 Как проверяем «другую учётную запись»** (AC-002). Автотест не умеет
  переключать учётные записи Windows, поэтому подкладывает ключ, который текущая
  учётная запись расшифровать не может, — для программы это та же ситуация.
  Настоящий запуск под второй учётной записью — ручная проверка на пилотном
  сервере при развёртывании, как уже отложенные проверки US-047 и US-050.
- **I-3 Где видна причина отказа не на Windows** (FR-005). Инсталляция пишет
  строку в свой журнал, как при ошибке настроек. У Control Plane до старта журнала
  нет, поэтому причина видна так же, как при отсутствующей настройке: в консоли и
  в журнале событий Windows. Отдельный журнал ради этого случая не делается.
- **I-4 Инструкцию развёртывания менять не нужно** (FR-007, AC-004). Нужные
  шаги появились в DC-2 вместе с версией требований v94. README комплекта
  развёртывания (вне репозитория) обновляется при пересборке комплекта перед
  этапом 3 пилота.

## 3. Открытые вопросы

Нет. Все три вопроса Story уже решены вами 2026-10-15: правило сначала в
требования (сделано в v94), старые ключи дочитываются до истечения, не на
Windows программа не запускается.

## 4. Что не входит в Story

- Где лежит папка ключей, права на неё и то, что она не попадает в резервные
  копии, — без изменений.
- Ключ сервис-аккаунта и секрет OAuth — другое хранилище, без изменений.
- Шифрование на других операционных системах — там программа просто не
  запускается.
- Удаление или перешифровка старых ключей.
- Создание учётных записей служб и настройка прав на папку — шаги
  развёртывания, не код.
- README комплекта развёртывания — он вне репозитория.
